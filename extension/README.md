# 观点分身 Chrome / Edge 扩展

当前版本：`0.4.0`（Edge 商店隐藏测试版候选包）

## 已实现

- 普通 HTTPS 网页中的悬浮球；
- 悬浮球可拖动，并记住最后位置；
- 悬浮球始终存在，单击可显示或隐藏工作台；
- 带使用说明、截取入口和未完成列表的工作台首页；
- 鼠标移入或点击后展开菜单；
- 回答选择模式与实时描边；
- 自动读取当前问题、目标回答、公开作者名和回答链接；
- 可移动、四边和四角均可缩放、可最小化的页面内悬浮窗；
- 题目、回答者和回答原文折叠卡片；
- 选择回答后跨页面保留原文、消息、窗口状态和位置；
- 多个未完成讨论分别缓存，新问题不会覆盖旧问题；
- 隐藏式会话抽屉，可随时切换缓存讨论；
- 多轮回答代理对话；
- 对话结束后的候选观点和回复草稿；
- 复制回复；
- 将本轮观点保存在扩展本地；
- 打开独立网页个人中心；
- 记住悬浮窗最后的位置和尺寸。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | Manifest V3 配置、知乎页面匹配、权限和资源声明 |
| `background.js` | 后端地址、网络请求、打开个人中心和工具栏图标事件 |
| `content.js` | 悬浮球、回答选择、窗口拖动缩放、对话和观点整理逻辑 |
| `overlay.css` | Shadow DOM 中的全部插件视觉样式 |

## Chrome 本地安装

1. 在网页项目目录运行：

   ```powershell
   npm start
   ```

2. 打开 Chrome 的扩展管理页面：`chrome://extensions/`。
3. 打开右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择当前这个 `extension` 文件夹。
6. 刷新已经打开的普通网页。
7. 在页面中找到“观点分身”悬浮球；选择回答时仍需进入 `https://www.zhihu.com/question/...` 页面。

## Microsoft Edge 本地安装

Edge 基于 Chromium，可以直接使用同一个 `extension` 文件夹，无需维护第二套代码：

1. 打开 `edge://extensions/`；
2. 开启“开发人员模式”；
3. 点击“加载解压缩的扩展”；
4. 选择当前 `extension` 文件夹；
5. 刷新已经打开的网页。

## 使用流程

```text
悬浮球
→ 打开工作台首页
→ 选择一个回答
→ 鼠标移动到目标回答并单击
→ 打开悬浮对话窗
→ 与回答代理讨论
→ 结束并整理观点
→ 修改候选观点 / 复制回复 / 保存本轮
```

在点击“保存本轮”之前，会话状态为“未完成整理”，会一直保存在 `chrome.storage.local` 中。关闭浏览器、重新启动或切换普通网页后仍可恢复。

## 当前后端地址

扩展当前连接：

```text
https://zhihu-social-demo-302050-11-1344805741.sh.run.tcloudbase.com
```

对应代码在 `background.js`：

```js
const DEFAULT_API_BASE = 'https://zhihu-social-demo-302050-11-1344805741.sh.run.tcloudbase.com';
```

以后更换正式自定义域名时需要同时修改：

1. `background.js` 的 `DEFAULT_API_BASE`；
2. `manifest.json` 的 `host_permissions`，替换为正式 HTTPS 域名；
3. 重新加载扩展。

## 当前限制

- 后端仍然使用规则型模拟代理，不是真实大模型；
- 本地原型只支持同一浏览器内绑定并同步到本地网页面板，尚不支持真正的云端账号与跨设备同步；
- 知乎改变页面结构后，回答识别规则可能需要更新；
- 浏览器内部页（`chrome://`、`edge://`）、扩展商店和部分受保护页面不允许内容脚本注入；
- 尚未发布到 Chrome Web Store；
- 正式发布前需要隐私政策、权限说明和完整安全审核。

## 当前本地账号绑定

点击扩展菜单中的“登录 / 打开个人中心”会打开带绑定标记的本地网页：

1. 用户在网页原型中登录或创建本地账号；
2. 扩展确认是 `localhost` / `127.0.0.1` 的本地面板；
3. 多会话缓存被映射到网页的“对话记录”；
4. 后续扩展缓存更新时，已打开的网页面板会同步刷新。

这是为了联调交互的本机原型，不是安全的公网账号系统。Chrome 与 Edge 的本地扩展存储彼此独立，只有接入后端后才能跨浏览器同步。

## 正式账号绑定应该怎样实现

当前网页的“注册/登录”只是 `localStorage` 交互原型，不能安全地给扩展当作真实账号。正式版本应使用后端授权流程：

1. 扩展点击“登录 / 打开个人中心”，跳转到网页登录页并携带一次性随机绑定码；
2. 用户在网页完成登录并明确确认“绑定此扩展”；
3. 网页后端把一次性码兑换成短期访问令牌与可撤销刷新令牌；
4. 扩展把令牌保存在 `chrome.storage.local`，请求接口时使用 `Authorization`；
5. 后端依据用户 ID 保存会话、观点记忆和代理等级，网页与 Chrome / Edge 才能读取同一份数据；
6. 个人中心提供“已连接设备”和“解除绑定”，令牌失效后必须重新登录。

不要读取或复用知乎 Cookie，也不要把用户邮箱直接当令牌。账号绑定依赖真实用户系统、HTTPS 和数据库，部署公网后再接入最合适。

## 给其他用户安装

网页不能静默替用户安装扩展，这是 Chrome 和 Edge 的安全限制。可采用两条路径：

- 内测：网页提供 ZIP 下载，用户解压后在开发者模式中加载；
- 正式发布：分别提交 Chrome Web Store 和 Microsoft Edge Add-ons，网页上的安装按钮跳转到对应商店，由用户确认安装。

本项目网页的“安装浏览器扩展”按钮已经提供测试版 ZIP 下载和两个浏览器的安装步骤。

## 数据边界

扩展不会自动扫描和上传整页内容。只有用户进入“选择回答”模式并单击某条回答后，才会提取：

- 当前问题标题；
- 被选择的回答正文；
- 回答公开作者名；
- 回答链接。

这些内容会发送到配置的观点分身后端，用于本轮回答代理对话。
